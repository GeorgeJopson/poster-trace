# The scan redirect is a Netlify Edge Function, outside Next and the layers

This supersedes ADR-0017, ADR-0015's decision to record scans in Next's `after()`, and ADR-0014's decisions that the target is read through `ScanTargetLookup` and checked with `CampaignTarget.create`. `/redirect/{posterId}` is served by `netlify/edge-functions/redirect.ts`, not by a Next route. On a cold scan, about 3.4 s of 4.2 s went on Netlify starting the Next server function before 5 ms of redirect code ran, as measured on 2026-11-22 with the instrumentation on the `perf/redirect-timing` branch. An edge function starts in tens of ms, so a cold scan now waits mostly on the database. Recording scans best-effort after the redirect (ADR-0015) is unchanged.

## Decisions

- **The edge function handles scans itself, outside the layers.** The edge runtime is Deno, which needs file extensions and doesn't read tsconfig `paths`, so it couldn't load `ScanService` or the Drizzle adapters. It has its own UUID check, target query, and scan insert that skips a poster deleted in the meantime. This is a deliberate exception to ADR-0001's layering. Two things in it must stay in step with the app: its UUID check with the domain's `isUuid`, and the `/poster-not-found` path with the page's route.
- **The layers no longer model scans being recorded.** With nothing else reading a target for a scan or recording one, `ScanService`, `ScanTargetLookup`, the `Scan` aggregate, `ScanId`, `ScanRepository` and their Drizzle adapters were deleted, which supersedes ADR-0017. Scans are still read through `PosterAnalyticsLookup`. With no `ScanId` left, scan ids are plain UUIDs generated wherever a scan is stored: by the edge function, and by the seed script and tests. This is an exception to ADR-0004.
- **The stored target is followed without being checked again**, a deliberate exception to ADR-0006. Only `CampaignTarget.create` writes targets, so every stored one has already passed its rules. Re-checking would mean a third copy of those rules to keep in step. If the rules on targets are tightened, the stored targets must be migrated at the same time, as ADR-0006 already requires. Browsers also ignore a `Location` header that isn't a web address, such as `javascript:`.
- **An unknown or malformed poster id gets a "poster not found" page, with a `404`.** This replaces ADR-0014's plain-text `404`. Someone scanning an old poster now sees an explanation instead of the bare words "Not found". The edge function fetches the Next page at `/poster-not-found` and returns its HTML with status `404` and `Cache-Control: no-store`, so the scan URL stays in the address bar. It passes on only the `Cookie` and `Authorization` headers, so that a deploy preview's access protection lets the page through and the page comes back uncompressed. If the page can't be fetched, or returns an error, the scanner gets a plain-text `404` instead. A redirect to the page was rejected because an unknown poster would then look like a successful redirect.
- **It queries with `getDatabase().sql`, not Drizzle.** Two short queries don't need the schema or the ORM. The client is created once and reused, because every `getDatabase()` call opens a new connection pool. It sends `scanned_at` as an ISO string, as Drizzle does: the column has no time zone and holds UTC, and the driver would turn a raw `Date` into local time.
- **`context.waitUntil` replaces `after()`.** It does the same job: it keeps the edge function alive until the scan is stored, without making the scanner wait.
- **The Next route is gone, with no fallback.** Keeping it behind `onError: "bypass"` would give a second implementation of a permanent contract that no test exercises.

## Considered Options

- **Pre-bundling the layers with esbuild into the edge function.** It was rejected because it adds a build step, a generated file and a watch process for `netlify dev`, just to reuse about 30 lines of rules.
- **Making the shared code Deno-compatible**, with `.ts` extensions, an import map and no `server-only` in `ScanService`. It was rejected because the scan path would then use a different import style from the rest of the codebase.
- **A small standalone Netlify Function on Node.** It was rejected because it would start in hundreds of ms rather than tens, with the same duplication.
- **A scheduled ping to keep the Next function warm.** It was rejected because it doesn't help when Netlify starts an extra instance, and it would stop the database from scaling to zero.
